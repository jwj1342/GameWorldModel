# 奖励一致性：探索统计与正式结论的边界

`scripts/check_reward_agreement.py` 比较奖励和真值轨迹误差的排序。来源关联已接入前置门禁，
但坐标/身份及自动PTS核验尚未完成，仍输出 `protocol_status=not_verified`，结论为“目前无法判断”，不预设感知是唯一原因。
不得将描述性相关系数当作真实视频训练有效、方法胜负或因果关系的证明。

## 可用性与分族统计

- `reward_status`、`gt_status` 单独表示两列的可用性；只有 available 且数值有限才纳入。
- 有实际对象观测和已解析ID时，奖励0是有效值，不能以大于0筛选。
- 没有观测或存在未解析ID时，保守标不可用，保留 `reward_raw` 作为原始计算输出，
  不将默认0当作实测。当前无法区分“对象确实缺失”和“ID命名不对应”，因此不猜测，
  需要后续身份协议解决；部分ID未解析时整个奖励暂不可用。
- 未带状态的旧报告不自动被判为可用；不按零/非零猜状态，不改原始历史JSON。
- 两族候选分别计算，不混合不同基准的分数。相关统计使用未四舍五入的数值。
- 默认至少3个可用样本，函数参数 `min_samples` 可提高要求；两列任一恒定或结果非有限，
  返回不可计算原因、null系数和明确的纳入/排除索引。低样本相关和p值只是描述，不足以支持泛化。
- 入口输出 `agreement_by_family`；旧顶层 `spearman_rho`/`p_value` 保留为null，
  不再输出混池系数。`n_comparable` 是各族纳入行数之和，不代表混池统计。
- 单调性缺数据时为null，不报false或成功。JSON写出禁止NaN/Infinity。

`graded_candidates()` 只平移对象，不移动静态结构和相机，因此命名为“对象整体平移”，
不是全场景坐标原点变换。相对未知真值不保证质量随扰动严格递减。

## 来源与执行门禁

入口需要显式 `--video`、`--associations`、`--duration`。复用
`gwm.feedback.ground_truth_source.resolve_ground_truth()`（此前本地来源评测工作的通用实现），
不再固定读取手写Program。关联清单匹配实际视频SHA-256，检查独立参考Program与生成记录的
哈希、唯一人工confirmed记录和零起点/正常速度的已审核时间范围；不按名称兜底。
哈希和确认字段只是可追溯的人工声明，不自动证明生成记录内容或语义真值正确。
Evidence还必须声明同一视频哈希，候选Program时长必须覆盖目标区间，关键帧时间合法。
所有来源输入在采集后复核；发生变化则拒绝统计，不以旧数据继续报结果。

示例（路径均为使用者自行准备的已审核材料，不自动生成或确认）：

```bash
python scripts/check_reward_agreement.py --run RUN --work NEW_WORK \
  --video VIDEO --associations REVIEWED_ASSOCIATIONS --duration SECONDS
```

默认报告放在新的work目录；已有报告/非空work拒绝覆盖。旧CLI不提供来源参数时返回
source_rejected及原因，不执行编译或渲染。来源不通过、参考编译/录制失败返回非零。
单候选编译、渲染、奖励、录制、GT计算失败保留阶段诊断并继续其他候选，报告
partial_execution_failure并退出1，失败候选的正式指标为null，不进入相关性。
空状态、时间非有限/非递增以及未覆盖目标起止时间的录制拒绝，避免短录制冒充完整评测。
此入口显式启用 `record.mjs --include-endpoint`，按10fps加采目标终点；录制器默认仍保持原来的
半开区间行为。闭区间模式核对内核实际state.t与请求时间，入口核对完整时间网格，不能仅凭
0和终点两条状态就冒充完整录制。非整帧时长的最后间隔可能不足一个采样周期，JSON保留真实时间。
Evidence帧的frame_index在副本中适配为旧奖励接口的index，并核对keyframe引用和时间，不补造编号。
调用脚本需要新增视频、审核关联、时长参数；CLI非零退出将通过set -e传回调用方，不打印伪成功。
没有修改原指标算法或自动对齐坐标，也没有重新运行旧实验。
