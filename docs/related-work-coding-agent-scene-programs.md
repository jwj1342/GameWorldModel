# 相关工作补充：用编码智能体生成显式场景程序

`related-work.md` 的调研停在 2026-09-18。而 GPT-6 Astra 在 2026-09-03 发布之后，
九月和十月出现了一批「让编码智能体写出显式场景程序」的工作，其中至少一篇已进
NeurIPS 2026。这一篇把那一批整理出来，回答三个问题：我们的基础方法是不是走错了、
别人做到什么程度、哪些做法我们该直接拿过来。

结论先说：**方法方向没有走错，这是当前一条热门且已被顶会认可的路线。但我们在三处
具体做法上落后，而且其中两处正是我们现在卡住的地方。**

## 这一批是什么

| 工作 | 输入 | 产出 | 关键做法 |
|---|---|---|---|
| LEGO-Anything（arXiv 2609.36380，09）| 单图 | Blender 代码 | 智能体闭环：写码 → 执行 → 看渲染 → 改 |
| NeoWorld-Pro（arXiv 2608.24212，**NeurIPS 2026**）| 单图 | Blender Python → URDF + USD | **物理在环**：Isaac Sim 里跑，不合理就修 |
| NeoWorld-3（arXiv 2610.27690，10）| 单图 | 代码定义的物理世界 | — |
| Agentic Real2Sim（arXiv 2607.19190）| 视频（DROID 机器人）| MuJoCo episode | 偏机器人数据 |
| Agentic RSR（arXiv 2610.10479，10）| 工作区视频 + 机器人模型 | MuJoCo | 用已知机器人尺寸定米制尺度 |
| LiteReality-Agent | RGB-D | 可 articulate、simulation-ready 室内场景 | 把重建当软件工程做 |
| BVB（arXiv 2609.15478）| 视频 | Blender 程序 | 是个基准，不是方法 |

更早的前身：SceneCraft（2024，LLM 写 Blender 代码）、VIGA（arXiv 2601.11109）、
Thinking in Blender（arXiv 2606.02580）、Code-as-room（arXiv 2605.18451）。

## 对 `related-work.md` 里「定位」那一节的影响

原来的说法是「现有工作四支各占一角，没有系统走通单目视频 → 带时序与动力学的场景
程序 → Web 引擎」，并把「4D（动态）」和「程序化表示」两环同时缺失作为本课题的位置。

**这个定位基本还成立，但缝隙比九月窄了：**

- NeoWorld-Pro 已经做到「单图 → 程序 → 关节 + 物理属性 → 仿真器里验证」。
  **程序化表示这一环不再是空白**，缺的只是视频输入和时序动力学。
- Agentic Real2Sim 和 Agentic RSR 确实吃视频，但**都绑在机器人数据上**
  （DROID episode、工作区视频 + 已知机器人模型），不是任意视频。
- 没有一篇同时做到「任意单目视频 + 观测到的运动 + 可交互程序」。

所以我们的位置仍在，但**写作时不能再说「没人做程序化场景表征」**，必须说清楚我们
和 NeoWorld-Pro 的差别在输入模态和时序建模上。

## 五条可以直接拿过来的做法

### 一、配对容差应该是相对的，不是绝对的

LEGO-Bench 的几何分 `R` 是 F@5%：把可见表面投到图像平面，按实例掩码分到物体上，
逐物体算精确率和召回，**容差是 `τ(g) = 0.05·z(g)`，随深度缩放**。

我们的 `scripts/eval --max-dist` 是**绝对米制**（当前 0.45 米）。这件事我们自己
踩过——绝对阈值不是尺度不变的，在小场景里等于「什么都能配上」，在大场景里又过紧。
LEGO-Bench 用相对容差是对的，**这一条值得直接改**。

注意一个差别：他们**不做规范对齐**（"compared in camera coordinates without
alignment"），而我们做偏航 + 水平平移对齐。两种口径不能混着比。

### 二、关节不要靠几何推断

这是最要紧的一条。NeoWorld-Pro **根本没有单独的关节检测方法**——由 MLLM 从图像
语义直接生成关节程序（论文举的例子是「从看得见的把手推断抽屉的内腔」），然后
**用物理去修**。

他们的关节指标：

| | NeoWorld-Pro | 最强基线 Articraft |
|---|---|---|
| 漏检率 | **11.83%** | 22.45% |
| 类型错误 | **18.78** | 29.39 |
| 轴误差 | 28.52 | 30.14 |
| 支点误差 | 0.19 | 0.23 |

对照我们：关节那一档在神经感知下 **0/7 全错**，全真值几何 + 全真值分割下也只有
**1/13**。根因已经查清是 #7 的 ICP 伪造转动（静止物体被解出 26.6° 转动，而铰链
门槛是 8°），而那条线上已经排除了二十条修法。

**也就是说：我们在用一条已经证明走不通的几何路线，去做别人用语义先验 + 物理验证
做成的事。** 这是本次调研最值得行动的一条。

### 三、物理当验证器，不只当运行时

NeoWorld-Pro 的物理在环分两层：

- **物体级**：URDF 在 Isaac Sim 里跑自由落体和受力扰动，一个看视频的 MLLM 评审
  关键帧并提修改建议。**改动被限制在惯性参数、关节限位、阻尼、原点和碰撞几何**，
  不动运动学拓扑和可见几何。
- **场景级**：用 CEM 优化每个物体的四维扰动（平面平移、偏航、对数尺度），奖励
  = 语义 MLLM 分 + 穿模惩罚 + 漂移惩罚。

消融（表 4）：完整方法成功率 **92.85%**，去掉语义分 48.81%，**开环 44.05%**。
**闭环把成功率翻了一倍多。**

我们已经有 Rapier 在运行时跑物理，但只用来「跑」，没用来「验」和「修」。
这条的成本不高、收益有先例。

### 四、但不要盲目上智能体自评

LEGO-Anything 量了三个失败模式，其中两个对我们是警告：

- **迭代中回退**：GPT-5.6-sol 有 **29.6% 的编辑让分数变低**；最终提交比它自己
  最好的中间结果低 3.2 分。
- **自评不可靠**：让模型二选一判断哪个渲染更好，和指标方向的一致率——
  **几何上自评 45.8%（低于 50% 的随机水平）**，外观上 62.2%。跨模型评审
  45.4% / 63.9%。

**几何自评低于随机**，这是个硬结论。我们现在是单趟确定性翻译，天然没有这两个问题。
所以如果要引入智能体闭环，**必须带版本控制和外部判据**，不能让模型自己说好不好。
LEGO-Plugin 的三个模块正是针对这个：增强初始化（VGGT 恢复相机）、接地式精化
（SAM 3 + Depth Anything V2 做显式残差）、**版本控制（接受 / 修复 / 回滚）**。

### 五、外观要量，但不是和 3DGS 比

**这一批没有一篇拿 3DGS 或 NeRF 作对比。** NeoWorld-3 的开场白直接写
"Simulation-ready world reconstruction demands physical interactivity beyond
visual realism"。

但他们**确实量外观**：LEGO-Bench 的 `A` 是「用标准引擎重渲染，和参考图逐像素比，
最大通道误差 ≤ 30/255 的像素占比」。总分 `S = 均值( ½(R+A)·V )`，失败算 0。

一个有意思的对照：Gen3DSR 的室内几何分 **65.4%**（高于 GPT-6-astra 的 52.4%），
但外观分 **0.0%**，总分只有 30.1%。**几何和外观是可以分开赢的**，而我们目前的
处境接近 Gen3DSR——有一点几何，外观近乎没有（形状种类准确率 0.300，所有物体
渲成盒子）。

## 从生成的场景里读视觉任务（LEGO-World）

把生成出来的场景当成一个世界模型，从里面读检测、分割、深度：

| 任务 | 指标 | 从场景读出 | 专用模型 |
|---|---|---|---|
| 检测（COCO val2017）| Box AP ↑ | 30.14 | DINO 59.88 |
| 分割（LVIS v1 val）| Mask AP ↑ | 14.75 | SAM 3 53.96 |
| 深度（ETH3D）| AbsRel ↓ | 0.1554 | Depth Anything 3 0.0783 |

大约是专用模型的一半。作者的结论是「有希望但还不够精确」。

## 我们还站得住的差异化

1. **视频输入，而且用观测到的运动**。这一批主流是单图；做视频的都绑在机器人数据上。
   我们的 `motion` 字段和第一档（观测运动回放）在这批工作里没有对应物。
2. **样式与行为分写，而且在量**。没有检索到别人测解耦度。我们的行为漂移 0.207 米 /
   样式响应 0.247（见 #52）可能是新的。
3. **带真值程序的基准**。LEGO-Bench 是 simulator-grounded 的 208 张图；我们的数据
   由生成器产出、**有已知真值程序**，能算精确的逐物体配对指标，并且支持成对样本
   （同行为换样式）。这是我们手上独有的东西。

## 为什么在外观上比不过 3DGS，以及空白在哪

这一节不是文献摘录，是上面那批材料加上我们自己测量之后的分析，供写 motivation 用。

### 这是容量和结构的取舍，不是优化不够狠

| | 3DGS / NeRF | 场景程序 |
|---|---|---|
| 自由参数 | 约 10⁶–10⁷（每个高斯：位置、协方差、不透明度、球谐）| 约 10²–10³（N 个物体 × 位姿 / 形状 / 材质）|
| 优化目标 | **直接最小化与输入像素的光度误差** | 完全不碰像素 |
| 假设空间 | 任意斑点场，**包含**真实场景 | 资产库 + 基本体，**不包含**大多数真实物体 |
| 离散决策 | 没有 | 物体数、类别、基本体类型、关节类型，**全不可微** |

最根本的是第三行：**不是我们优化得不够狠，是真实场景根本不在我们的假设空间里。**
一个真实的笔记本不是盒子，资产库里也没有它。3DGS 不需要"认识"任何东西，
它只要把斑点摆到降低像素误差的地方。

第四行是第二重障碍：程序合成必须做离散选择，而这些选择不可微。
"检索哪个资产""这是铰链还是滑轨"都没法反向传播。

### 3DGS 正在从另一头走过来，撞上的墙正好是我们免费拥有的

有一条活跃的线在给高斯加物理：DecoupledGaussian（CVPR 2025）、PhysSplat
（ICCV 2025）、Scene-Level Heterogeneous Physics（arXiv 2606.21753）。
他们自己写的困难：

| 他们的难点 | 出处原话 | 我们这边 |
|---|---|---|
| 被遮挡 / 看不见的几何 | "no GS or NeRF method could restore objects **occluded by the scene** or missed due to object removal" | 直接给完整的几何体 |
| 物体能否真正脱离表面 | 早期方法里物体 "remain **constrained to the contacted surface**" | 从一开始就是独立刚体 |
| 从静态捕获推物理属性 | "extremely challenging task due to **limited supervisions**" | 表示里本来就有质量、摩擦这些槽位 |
| 抽网格 | "Gaussians are **unorganized**" | 不存在这个问题 |
| 接进物理引擎 | "physics engines **weren't designed for** Gaussian representations" | 本来就是为引擎生成的 |
| 只能回放不能外推 | "**Replay-based methods only play back** captured or generated motion, so they **can't simulate new dynamics**" | 正是核心主张里的"可外推" |

DecoupledGaussian 为了补一个物体的背面要用 Poisson 场填充加反复雕刻，
而且作者明说这套**牺牲纹理保几何**。

### 真正的不对称

> **外观对我们是容量问题，结构对他们是表示问题。**

容量问题可以买——更大的资产库、更深的组合、或者混合表示。
表示问题买不到：没法通过"优化得更狠"从一团斑点里长出"这是一扇门，它绕这根轴转"。

这是支撑本课题方向最硬的一条论据，而且它来自对方自己写的 limitation。

### 我们自己最大的困难

不是渲染不够真，是**假设空间不含内容，加上整条链路没有任何像素反馈**：

- 资产检索成功率 45%（118 个物体检到 53 个），而且当前基准真值全是基本体，
  **检索成功反而在形状种类上算错**
- 形状种类准确率 0.300，超过一半的物体渲成盒子
- **从感知到合成到编译，没有一处拿渲染结果和原视频比过**

第三条最要命，因为它可以修。

### 两个没人做的空白

**一、把光度一致性当损失，而不是当分数。** LEGO-Bench 的外观分 `A` 是"重渲染后
逐像素比"，但它只被当成评测指标。没有工作把它接成程序合成的**优化信号**
（渲染程序 → 和原帧比 → 改程序 → 再比）。LEGO-Plugin 的 grounded refinement
用 SAM 3 + Depth Anything 做显式残差，已经在摸这个边，但没有直接用像素。

**二、3DGS 与场景程序的结合整体是空白。** 检索下来没有任何工作把两者放在一起。
给高斯加物理的那一线，和让智能体写程序的那一线，目前互不引用。

### 一个我们自己没用上的容量来源

内核的 `kernel/scene.js` **已经支持 `kind: "composite"`**（带 `parts` 的组合体，
见第 104、115 行），但它只能通过类名正则的兜底分支触达（`tree|plant|bush`、
`train|car|cart|...`）。实测产出里 **70 个物体节点全部是 `asset`，一个组合体都没有**。

也就是说：**提升假设空间容量的机制已经在代码里，只是从来没被用过。**
用组合体加深结构，比引入非程序的残差更可取——因为组合体仍然是程序，
仍然可编辑、可仿真、可外推。

## 一个候选方向：把 3DGS 当教师，而不是当残差

这一节记的是 2026-10-23 讨论里成形的一个想法，以及围绕它查到的东西。
**它目前只是候选，没有实验。**

### 框架：蒸馏，不是残差

初版的想法是"程序管结构、高斯管外观残差"。那个版本有两个硬问题：

1. **分解不可辨识。** 残差分支足够强的话，盒子摆错位置高斯也能补回来，渲染照样
   好看——于是程序不再是场景的忠实结构描述，拖动物体时行为是错的，但你从渲染上
   看不出来。
2. **残差在新位姿下会塌。** 高斯只在观测到的视角上拟合过，物体一转到没见过的朝向
   （而那正是"可交互""可外推"的定义）残差就失效。这恰好把 3DGS+物理那条线已经撞上
   的墙（"can't simulate new dynamics"）引进我们的强项里。

改成**蒸馏**之后这两个问题都消失了：3DGS 是**教师**，程序是**学生**，
**最终产物只有程序**，高斯不进交付物。没有残差分支可以吸收结构误差，
也没有外观缓存会在新位姿下塌。

### 教师能给的，原始视频帧给不了

如果只是想要光度损失，直接拿视频帧比就行，不需要先拟合高斯。先拟合的价值在四点，
其中第一和第三是真正关键的：

1. **新视角监督。** 视频只覆盖相机实际走过的轨迹，而高斯能渲染相机从未到过的视角。
   这样就能监督程序**没被观测到的那些面**——而那正是我们的盒子最差的地方。
   原始帧给不了这个。
2. **稠密几何代理。** 在我们深度后端失败的地方也有一个表面估计。
3. **多视角一致的去噪目标。** 高斯在多帧上平均，抑制逐帧噪声。这一条对我们特别
   对症：实测逐帧包围盒中心的抖动是节点自身对角线的 **0.43–0.46 倍**，而且是
   **单调漂移**（见 #56），根因是"框跟的是可见表面，不是物体"。
   一个多视角一致的目标正是治这个的。
4. **可按物体分解的目标。** 配上掩码之后每个物体有自己的高斯集，可以逐物体拟合，
   而不是对着整帧算一个损失。

### 已知的坑，以及已知的解法

把结构化基元和高斯放在一起训练，有一个有文献记载的失效模式：

> Naively training 3D Gaussians and room layout meshes jointly can result in
> **ambiguity issues, leading to a single instance being represented by both
> primitives**. We address this issue by **using SAM masks as a guide**.
> ——《Integrating Meshes and 3D Gaussians for Indoor Scene Reconstruction with
> SAM Mask Guidance》（arXiv 2407.16173）

这正是上面第 1 条担心的实测版本。**而它的解法是用语义掩码做引导**——也就是说
"让物体去拟合语义遮罩"这个直觉，恰好是这个已知失效模式的已知对策。

同一篇还给了一条支持结构化表示的论据：

> A simple plane composed of a few colors can be effectively represented with a
> small number of meshes, whereas representing it with 3D Gaussians requires a
> **significantly larger number**.

高斯在平坦区域是浪费容量的。这说明两种表示**各有擅长的区域**，不是单纯的强弱关系。

### 它解决不了什么

**蒸馏改善的是拟合，不是表达力。** 如果真实物体是一台笔记本而我们的词汇表只有
"盒子"，更好的教师只会更精确地告诉你盒子有多不像笔记本——最好的盒子仍然是盒子。

所以这条路**必须和加深组合深度一起做**（见上一节：内核已支持 `composite`，
但我们一个都没产出过）。教师告诉你哪里错，组合体给你改正所需的词汇。
两者互补，不是替代。

### 为什么说它是空白

检索下来：

- 没有任何工作把 3DGS 蒸馏进**结构化场景程序**；
- Feature Splatting 做的是把视觉语言特征蒸馏**进**高斯（方向相反）；
- ShapeSplat 是 CAD → 高斯（流向相反）；
- 把光度一致性当**损失**而不是当分数，在编码智能体那一线也没人做
  （LEGO-Bench 的 `A` 只是评测指标）。

### 成本上的提醒

逐片段拟合 3DGS 本身是有成本的。按 #21 的实测，我们一趟 2000 条的重建已经约
40 GPU 小时，而账户的稳态额度约 12.6 张 L40S、近期已用到份额的 1.79 倍。
加一层高斯拟合之前要先算这笔账，或者只在子集上做教师。

### 一个不需要高斯的弱化版本

如果先不想引入高斯，这个想法有一个更轻的版本：**可微渲染**。把程序渲出来、
和原帧比、梯度回传到**连续参数**（位姿、尺寸、颜色），离散选择（几个物体、
哪个基本体、什么关节）仍然留给智能体搜索。

它拿不到"新视角监督"那一条，但其余三条收益都在，而且没有第二套表示要维护。
可以作为先走一步的版本。

## 再进一步：把"元素库"学出来

2026-10-23 讨论里的第三个想法：不要手写资产库，也不要固定的几个基本体，
而是**从一个训练集里把可组合的"元素库"学出来**。

这个想法有成熟的谱系，而且其中一篇的标题几乎就是它本身。

### 谱系

| 工作 | 做什么 | 对我们的意义 |
|---|---|---|
| **DreamCoder**（2020）| wake–sleep 的库学习：从已解的程序里挖抽象，用"程序似然 vs 库复杂度"的权衡来取舍 | 原型，但见下面的警告 |
| **ShapeMOD**（arXiv 2104.06392）| 3D 形状程序的宏操作发现 | 指出更早的文法归纳只能处理上下文无关语言 |
| **ShapeCoder**（arXiv 2305.05661）| 标题即"**从无结构基元中发现视觉程序的抽象**"，压缩目标，能处理复杂参数化重写 | **最接近这个想法的工作** |
| **ShapeLib**（arXiv 2502.08884）| 用大模型来设计这个库 | 它称 ShapeCoder 是 3D 库学习目前最好的方法 |

### 三条必须先知道的警告

**一、DreamCoder 在 3D 上是失败的。** ShapeCoder 作者在补充材料里写：

> When we attempted to run DreamCoder over PartNet data we observed it
> **did not find any solutions**.

他们给的原因是 DreamCoder 没有机制处理连续参数之间的关系，而那对视觉程序至关重要。
所以"照搬 DreamCoder"这条路有人试过并且失败了。

**二、ShapeCoder 的产物对大模型不友好。** 作者自己写：

> We experiment with how well LLMs can interact with ShapeCoder programs, and
> find that this is **challenging for frontier models**. ShapeCoder functions and
> parameters **do not have semantic-aligned names**, and tend to **over-focus on
> local patterns, especially when discovered from small seed sets**.

这对我们是直接的问题：我们整条链路（以及整个编码智能体那一波）都依赖模型去读写
这个词汇表。学出来一个模型读不懂的库，等于没学。ShapeLib 用大模型参与设计正是
为了解决这一点。

**三、小种子集会让抽象偏向局部模式。** 我们现在的批次是 12 条片段。
库学习要的是语料规模，这个量级远远不够。

### 训练集从哪来——这是最大的风险

如果从**我们自己生成器产出的真值程序**里学库，学到的就是生成器的词汇表。
那是循环的：我们会得到一个在自己的合成基准上完美、在真实视频上无用的库。
**这个风险必须在设计实验之前就想清楚。**

一个更有意思的版本是和上一节接起来：

> ShapeCoder 的输入是"**无结构基元**"。而逐物体分解之后的高斯，正是一堆无结构基元。

也就是说：**用 3DGS 当教师产出无结构基元 → 在语料上做压缩式抽象发现 → 得到元素库**。
这条不需要真值程序，监督来自真实视频本身，绕开了上面那个循环。
检索下来没有人这么做过。

### 还有一块完全空白：行为的词汇表

上面所有工作学的都是**几何**抽象。没有人学过**行为**的词汇表——
哪些运动模式反复出现、哪些关节类型可以组合、哪些交互可以复用。

而我们的表示里 `motion` 和 `interaction` 和几何是并列的。
**如果"元素库"要学，行为那一半比几何那一半更没人做过，也更贴近本课题的主张。**

### 时间上的判断

这是一个**独立研究课题的体量**，不是一个修补。DreamCoder 到 ShapeCoder 到 ShapeLib
是五年三篇。按 #21 记的投稿时间（CVPR 2027，11-16 截止），
**这条不属于这一轮**。记在这里是为了不丢掉，以及在写 future work 时有据可依。

## 两个 MVP 的结果，以及它们对叙事路线的含义

2026-10-23 跑了两个决定性实验，目的是在投入之前判断「组合深度」和「3DGS 当教师」
哪条更有希望。**两条路最便宜的入口都关上了**，而且过程中发现了一个现有指标的缺陷。

探针在 `scripts/probe_photometric_signal.py` 和 `scripts/probe_shape_headroom.py`。
后者需要 PR #76 才有的 `effective_shape` / `scene` / `shape_kind`，
所以它提交在那条分支上，不在本分支。

### MVP 一：整帧比较带不带参数信号——不带

「教师」路线最便宜的入口是：渲染和原帧比，拿分数当监督。先验这个入口通不通——
把一个物体按已知幅度挪动，看分数怎么响应。五条片段，扰动画面里最大的那个物体：

| 判据 | 像素一致率 | DINOv2 余弦 |
|---|---|---|
| 单调（幅度越大分数越低）| 1/5 条，且那条是全零的退化情形 | 2/5 条，同样含一条退化 |
| 0.05 m 效应 ÷ 方向噪声地板 | 中位 **0.37** | 中位 **0.35** |

**要远大于 1 才能当监督信号，实际是 0.35。** 最小那一档扰动带来的变化，比
「换个方向挪同样距离」的差异还小三倍。

更糟的是**方向会反**：test_00006 上把物体挪开 0.40 m，DINOv2 认为**更像**了
（0.6576 → 0.6925）；test_00003 上像素一致率同样随扰动上升。

**这连带照出一个现有指标的缺陷。** `gwm/feedback/likeness.py` 用的正是整帧 DINOv2
余弦，注释里说它是"整条链路最该有、却一直没有的那个数"。
而它在四条非退化片段里有两条方向是反的——**这个指标会奖励把物体挪开**。

要说清楚这个实验**没有**否定什么：它关掉的是「整帧标量分数」这个入口。
真正的教师能给的是**逐物体的稠密三维目标**（新视角、去噪表面、按掩码分解的外观），
那是另一回事，这里没测。

### MVP 二：形状种类的上界只有五个点

「组合深度」路线的问题是：把形状修对，最多能买到多少？用预言机定上界——
拿真值程序，只把每个几何退化成**同尺寸的盒子**，其余一字不改，再和原真值比。

真值形状构成：box 97、sphere 16、cone 9、cylinder 6（退化了其中 31 个）。

| | 退化之后 |
|---|---|
| 物体召回 | 56/59 = **0.949** |
| 物体精确率 | 56/59 = **0.949** |
| 场景召回 | 125/128 = **0.977** |
| 形状对（边长比例）| 中位 **1.000**，毫发无损 |
| 尺度之比 | 中位 **1.000**，毫发无损 |

**把形状种类全毁掉，配对指标只掉五个点，形状对和尺度之比一点没动。**

两条结论：

1. **现有指标对形状种类几乎是盲的。** 形状对比的是边长**比例**，退化保尺寸所以
   它看不见；配对只看位置，所以它也基本看不见。
2. **组合深度推不动当前这几个数。** 上界五个点，而我们实际的物体召回是 0.356，
   离 0.949 的差距几乎全部来自形状种类**以外**的东西。

同样要说清楚没有否定什么：这是**指标空间**的代价，不是**观感**的代价。
一个该是球却渲成盒子的物体在配对指标上毫发无损，看起来却明显是错的。

### 对叙事路线的含义

把两个 MVP 放在一起，指向一个不太舒服但相当明确的判断：

> **我们既没有便宜的办法提升保真度，也没有能衡量保真度的指标。**

- 提升那一侧：两条路的便宜入口都关了（整帧光度无信号、组合深度上界五个点）；
- 衡量那一侧：配对指标对形状种类几乎盲，而唯一的"像不像"指标方向会反。

所以「我们把从视频重建可交互场景做得更好」这个叙事，**在当前的工具下既做不到也
证明不了**。

但反过来，这两个 MVP 本身构成了一个可以写的东西：**显式场景程序这条路上，
哪些显而易见的做法实际上不起作用，以及为什么**。配合此前已有的材料——

- 带真值程序、支持成对样本的基准（LEGO-Bench 没有成对样本）；
- 样式-行为解耦度的第一组数（检索下来无人在量）；
- 一串带对照的否定结果：ICP 伪造转动挡住关节这一档（二十条排除）、
  碎片合并五连败（几何/深度/外观三类信号、程序层与掩码层两个层面）、
  资产检索在基本体真值上**结构性地**拿不到分；
- 真值本身的两个生成器 bug，以及它们对指标的影响；

——这些合起来是「**这条路实际上难在哪，以及现有评测看不见什么**」，
而不是「我们做得更好」。

**这一节只摆证据，不替人做决定。**（后续：MVP 三把「哪一版没测过」这件事
查清楚了，并且推翻了本节对「偏位」的一处读法，见下面「MVP 三」。）两条路都还有没测过的版本：教师的稠密三维
目标那一版、组合深度在真实视频（物体本身就是多部件）上的那一版。
要继续投，下一个该测的是这两个，而不是再试一遍已经关掉的入口。

## MVP 三：漏掉的六十个点到底在哪

前两个 MVP 之后还剩一个没人知道答案的数。物体召回 0.356，MVP 二量到的形状预言机
上界 0.949，**中间差着将近六十个点，没有人知道它们分布在哪些失败模式上**。
这件事直接决定叙事：漏掉的物体如果是「检出来了只是位置差太远」，稠密三维重建修的
正是这一类；如果是「那个位置根本没有候选」，教师给不了语义，这条路白走。

探针是 `scripts/probe_recall_decomposition.py` 和 `scripts/probe_ground_penetration.py`，
提交在 PR #76 的分支上（要用那边才有的 `scene` / `shape_kind` 指标）。
不改程序、不喂预言机，只对已有的评测结果做归因。

规范对齐逐行照抄 `evaluate()`，并带两条硬性自查：复现出来的配对数必须等于
`evaluate()` 自己报的 `by_mean_distance`，复现的召回必须等于它报的 `recall`，
任何一条不过就不出数。这个坑踩过一次（早先一个探针漏了 `align_world` 的平移，
把「119 个簇对 128」读成 0.93），所以这次写成前置条件。

### 第一眼的结果，以及它为什么是错的

四个配置，容差 0.45 米，和各自 `*_eval.json` 里记的一致：

| 配置 | 召回 | 漏掉 | 占用 | 偏位 | 缺席 |
|---|---|---|---|---|---|
| 调参集，闸关 | 0.424（25/59）| 34 | 1 | 23（67.6%）| 10 |
| 调参集，闸 0.30 | 0.356（21/59）| 38 | 2 | 25（65.8%）| 11 |
| 留出集，闸关 | 0.292（14/48）| 34 | 0 | 21（61.8%）| 13 |
| 留出集，闸 0.30 | 0.208（10/48）| 38 | 0 | 16（42.1%）| 22 |

「占用」是最近的候选在容差以内却没配上（一对一指派或碎片），「偏位」是 1~4 倍
容差，「缺席」是 4 倍以外。照字面读，三分之二的漏检属于「东西检出来了只是放错
地方」，教师路线稳了。

**这个读法是错的。** 场景里到处都是节点的话，随便哪个位置附近都有一个，「偏位」
会被巧合撑起来。所以报了两个零假设，而且故意让它们偏向相反：

**甲，场景固有间距**——漏掉的物体到**最近的另一个真值节点**有多远。
它的洞在于把「我们预测了几个节点」混了进来：预测得少，「最近的预测更远」就天然
成立，跟放没放对无关。**甲偏向否定教师。**

**乙，密度匹配**——在真值场景的包围盒里均匀撒 512 个随机点，用**同一批**预测
节点量最近距离。预测的个数和位置一点没动。但真实物体不是均匀铺开的，它和预测
都往「有东西的地方」聚，均匀撒的点有一部分落在空处。**乙偏向肯定教师。**

| 配置 | 漏掉的物体到最近预测 | 甲：到最近的另一个真值 | 甲比值 | 乙：随机点到最近预测 | 乙比值 |
|---|---|---|---|---|---|
| 调参集，闸关 | 1.41 m | 0.98 m | 1.09 | 0.76 m | **1.84** |
| 调参集，闸 0.30 | 1.47 m | 0.95 m | 1.21 | 0.84 m | **1.75** |
| 留出集，闸关 | 1.54 m | 0.84 m | 1.85 | 0.81 m | **1.92** |
| 留出集，闸 0.30 | 1.99 m | 0.73 m | 2.38 | 0.99 m | **2.01** |

**两个偏向相反的零假设指向同一个方向，所以这件事定案了：**

> 漏掉的真值物体，到最近预测节点的距离，比场景里随便一个点还远。

「检出来了只是放偏了」那种情况下，漏掉的物体附近应该**特别**容易找到一个预测
节点（就是它自己，挪了位），距离该明显小于随机点。实际反过来——**漏掉的物体
待在预测特别稀疏的地方，那里本来就缺东西。**

所以「偏位」这一桶不能当成教师能修的份额，那个 67.6% 是读错了。
但这个结论指向下一个问题：**是什么在那些位置挖了洞。**

### 洞是这么来的：一两条片段整体规范失效

翻一条编译不过的片段时发现，管线**自己早就记着**：`meta.dropped_sunk` 里逐个列着
它因为「算出来在地面以下」而丢掉的节点，带 `bottom_over_height`（底面低于地面
多少个**自身高度**）。四个配置合计，被这样丢掉的占全部检出节点的 **16%~20%**，
中位陷进去**五到九倍自身高度**。

但这个合计数会骗人，把它按片段摊开才看得见真相：

| 配置 | 规范对齐退化的片段 | 这些片段丢掉 | **其余十来条片段丢掉** |
|---|---|---|---|
| 调参集，闸关 | test_00000 | 21 | **0** |
| 调参集，闸 0.30 | test_00000 | 15 | **0** |
| 留出集，闸关 | test_00002、test_00009 | 5 + 18 | **0** |
| 留出集，闸 0.30 | test_00002、test_00009 | 0 + 12 | **0** |

**所有沉底丢弃，无一例外发生在 `world_alignment_degenerate` 这个诊断亮了的片段里；
其余片段一个都没有。** 这不是弥散在全链路的深度误差，是**十二条里一两条发生全局
规范失效，那几条整场景下沉**。

这些片段的产出是这样的：

```
fx_00  test_00000   真值 7  配上 0  漏 7  全部落进「缺席」   预测 object 0 个
hf_00  test_00009   真值 7  配上 0  漏 7  全部落进「缺席」   预测 object 0 个
```

**规范一退化，整条片段一个物体都产不出来。** 调参集闸关那一档，「缺席」10 个里
有 7 个来自 test_00000 这一条；留出集 13 个里有 7 个来自 test_00009。

（合计掩盖分布，这个错我自己记过一次，这里又差点犯：先写成「五分之一的检出算到
地下」，按片段摊开才发现是一两条片段的事。）


**根因当天就查出来了**（写在 #84 里）。诊断读的是 `evidence.json` 里
`camera0_height_before_scale`——按估出来的地平面算，第一帧相机离地多高。
把全部片段按这个数排开，分布是分层的：

| 档位 | 估出的相机高度 | 凑到 1.2 米要乘的倍数 | 沉底丢弃 |
|---|---|---|---|
| 正常 | 0.85 ~ 1.12 m | 1.1 ~ 1.4 | 0 |
| 中间 | 0.21 ~ 0.35 m | 3.4 ~ 5.8 | 0 |
| **退化** | **0.035 ~ 0.077 m** | **15.6 / 30.5 / 34.3** | 21 / 5 / 18 |

**相机不可能离地四厘米。** 所以这不是尺度估偏，是**地平面被拟合到了相机跟前
那个面上**。管线接着把整个场景乘十五到三十四倍去凑 1.2 米的假设，于是全沉了。

这坐实了上面那句「最大的一块是工程 bug」：它有确定的机制、有现成的诊断码、
有两条具体的修法（加一条相机高度下限的闸；退化时兜底而不是产出空程序）。
一篇论文里写不下这个，但不修它，后面任何测量都在量它。

### 所以那六十个点是这样分的

- **整片失效**：一两条片段因为规范退化产出零个物体，它们的真值物体全算漏检。
  调参集闸关那一档占全部漏检的 7/34 ≈ 21%。这是**工程 bug，不是研究问题**，
  而且已经有现成的诊断码能抓它。
- **其余的漏检**：两个零假设都说不是「检出来放偏了」，而是那片位置本来就稀疏。
- **形状种类**：MVP 二量过，上界只有五个点。
- **一对一指派和碎片**（「占用」）：0~5%，基本不是问题。

**「组合深度」和「教师当打分器」这两条，都不对着上面任何一条大头。**

### 那「教师」还剩什么

MVP 一关掉的是教师的**一种**用法：当打分器，渲染出来和原帧比，拿分数指导参数
（效应/噪声 0.35，方向还会反）。另一种用法没测过——**当几何提供者**，直接替掉
现在这个「逐帧可见点集的汇总量」。仓库里已有的测量支持它，那些数是 #7 查运动
估计时顺带量到的，不是为教师做的，所以更可信：

| 做法 | 结果 |
|---|---|
| 掩码**完全准确**时，包围盒中心的位置误差中位数 | **0.244 m** |
| 沿视线推半个深度尺寸（「只看得见近侧」）| **过校正**，0.294 → 0.620 m |
| 每物体估一个与时间无关的刚性偏移 | 只改善 **8%**（0.154 → 0.142 m）|
| 换中位数 / 均值替代包围盒中心 | **更差**，0.244 →（0.541 / 0.469）|

机制写得很清楚：包围盒中心是可见点在各轴上 3/97 百分位的中点，**可见面一变两端
就变**。原话是「可见点集的任何逐帧汇总量都给不出干净的轨迹」。稠密三维重建给的
正好是跨帧聚合起来的完整几何，从机制上是对症的。

**但有三条必须一起说：**

**一，便宜版本试过了，只拿到 26%。** `gwm/perception/registration.py` 做的就是
跨帧累积成物体模型：位移误差 0.253 → 0.188 m，但静止物体漂移反而 0.182 → 0.286 m，
而且 ICP 会无中生有解出转动（#7）。教师这条路赌的是**全局光度优化比贪心序贯 ICP
好一个档次**，不是「没人试过跨帧聚合」。

**二，教师也看不见相机没绕过去的那一面。** 3DGS 只在被观测视角上有约束。
它能修「被看过但逐帧汇总不稳」，修不了「从头到尾没被看见」。这个天花板可量——
量相机对每个物体的角覆盖，还没量。

**三，教师有用的地方我们量不了，量得了的地方它和真值冗余。** 真实视频没有真值
程序，`eval.py` 直接标成不可评测；合成数据本来就是真值程序渲出来的。出路是
**模拟教师**——拿真值几何加可控噪声当教师信号，把噪声从 0 调到 3DGS 实际能做到
的水平，看召回怎么响应，回答「教师要多准才值得做」。

### 顺带：留出集的表少了一条片段，少的是最差那条

留出集的 `test_00002` 产出程序编译不过（五个物体全部陷进地面 2.7~3.9 米，
被内核的 `ground_penetration` 校验挡下）。`eval.py` 把它记进 `failed` 并排除在
汇总之外，于是留出集的「片段数」写的是 **11 而不是 12**。这不是隐瞒，
但**排除的恰好是最差那条**，所以留出集的数偏乐观。调参集两档都是 12，
留出集两档都是 11，跨集比较时要记得。

## 叙事路线：三个 MVP 之后的判断

三个实验合起来，可以把话说得比上一节明确：

**「我们把从视频重建可交互场景做得更好」这个叙事，现在仍然立不住**，但理由和
上一节写的不完全一样。上一节说「两条路最便宜的入口都关了」，现在还要加一条更难
反驳的：**我们连漏在哪都刚刚才搞清楚，而搞清楚之后发现最大的一块是工程 bug。**

- 整片规范失效（一两条片段产出零物体）：占漏检两成，**是 bug，不是贡献**；
- 其余漏检：两个零假设都说不是「检出来放偏了」；
- 形状种类：上界五个点；
- 一对一指派和碎片：0~5%。

把 bug 修掉能拿回两成漏检，但那写不进论文。而**写得进论文的那两条——组合深度、
教师当打分器——都不对着任何一块大头**。

**教师当几何提供者**那一条还活着，而且是三条里唯一有机制证据支撑的：包围盒中心
是逐帧可见面的汇总量，掩码完全准确时误差仍有 0.244 米，三条廉价修法全败。
但它要赌「全局光度优化比贪心序贯 ICP 好一个档次」，而序贯版本已经试过只拿到 26%。

**下一个该做的实验因此是明确的：模拟教师。** 在合成数据上拿真值几何加可控噪声
当教师信号，把噪声从 0 调到 3DGS 实际能做到的水平，看召回怎么响应。它一次回答
两个问题——教师要多准才值得做，以及在修掉规范 bug 之后还剩多少空间。
这个实验便宜、不需要 3DGS 管线、而且结论对「要不要投这条路」是决定性的。

**这一节仍然只摆证据。** 但有一件事现在可以确定地说：**先修 #84，再谈教师。**
在一两条片段产出零物体的情况下量任何东西，量到的都是那个 bug。

## 评估这一侧：已经有 benchmark 了，而且不止一个

2026-10-23 补查。之前这份文档只盯着「方法」那一侧，漏了一个要紧的事实：
**我们要做的这件事现在已经有公开 benchmark 了。** 自己从零造一个之前，
先得知道它们是什么、够不够用。

| 名字 | 输入 | 规模 | 评什么 |
|---|---|---|---|
| **Video2World**（arXiv 2610.04432）| 具身视频（机器人 + 人的演示）| 222 个重建实例 / 189 段视频 | 几何保真、动态保真、**功能正确性**三轴 |
| BVB（arXiv 2609.15478）| 室内视频 | 288 段视频 / 5130 个问题 | 重建成 Blender 动画场景，**不含物理和具身** |
| CineRecon（arXiv 2610.16577）| 影视、实拍、游戏 | 50 段参考 / 360 段标注 | 电影化重建，不是机器人或关节 |

**Video2World 是最接近的一个**，接近到必须正面回应。它的设定是：给智能体一段 RGB
视频和仿真器工具，让它建出对应的仿真环境**和机器人行为**，再用执行反馈去改。
九个前沿编码智能体，任务成功率从不到 5% 升到 15% 出头（从 Claude Opus 5 开始），
离「有人协助的重建」还差很远。

两件事值得注意。一是**成功率只有 15%**，这条赛道远没有被做完。
二是它的三轴里有一轴叫**功能正确性**——「这个世界支不支持可执行的交互」，
和我们的四档可交互性是同一个念头。

### 它够不够用

不够，但不是因为它差，是因为任务不是同一个：

- 它的视频是**具身演示**（机器人和人在操作），输出里**包含机器人行为**；
  我们的输入是一般视频，输出是场景程序，没有机器人；
- 它评的是三个聚合分数；我们的真值是**程序本身**，能做逐物体的精确配对；
- **它没有成对样本。** 同一个行为换一套样式、同一套样式换一个行为——
  这是我们核心主张第四条（样式与行为分写）唯一能被量到的方式，检索下来没人在做。

所以定位应该是：**我们自己的合成基准当主评测**（它是唯一能量解耦度的），
**同时在 Video2World 上报一组数当外部可比性**。只在自家基准上报数的论文站不住，
这一点要早做打算。

### 我们手里已有、别人没有的

1. **带真值程序**——不是聚合分数，是逐物体的精确配对；
2. **成对样本**（同行为换样式 / 同样式换行为）——解耦度的唯一量法；
3. **四档可交互性分级**，配一个固定的 three.js + Rapier 内核；
4. 一个**生成器**，所以规模可以往上堆。

### 缺的

- **规模**。现在是调参 12 条 + 留出 12 条，离 benchmark 差一个数量级以上。
- **真实视频的真值**。zx 拍的那几段没有真值程序，`eval.py` 直接标成不可评测。
  这是最硬的一块——教师有用的地方恰好是量不了的地方（见上一节）。
- **已发表 / 被人用过**的地位。


## 2026-10-23 下半天：两个创新点各推了一轮，四条路关闭

上面那几节停在「下一个该测模拟教师」。实际做下来比那个计划更具体，也更难看。
这一节记当天的结果，包括几条**被自己推翻的判断**——它们的价值在于省掉重走。

### 创新点一：原理成立，但管线里没有落点

**受控实验**：同样的掩码（真值）、同样的拟合器、同样的 210 个物体，**只换几何后端**，
看基本体种类（box / sphere / cylinder / cone）能不能从点云里拟合出来。

| 几何后端 | 逐帧拟合投票 | sphere | cylinder | cone |
|---|---|---|---|---|
| VGGT | 0.405（输「恒答 box」基线 0.714）| 12/22 | **0/22** | **0/16** |
| **真值** | **0.919**（赢基线 +0.205）| **22/22** | 10/22 | **15/16** |

**形状信息是在的，拟合器是对的，是几何质量把它毁了。** 这个离散选择上，
更好的几何值 **+0.51 准确率**。这是「稠密几何能监督离散程序选择」第一次有量化证据。

顺带两条：**逐帧拟合再投票（0.919）明显好过先并点云（0.800）**，和「并云被离群点
污染」那条旧结论一致；cylinder 即使在真值几何上也只有 0.455——真值里的柱体是
radius 0.144 / height 0.210 这种扁柱，和盒子本来就难分，那是形状本身的模糊性。

**但管线里兑现不了。** `shape_kind_accuracy` 恒为 0.0000，不是因为类名正则差，
而是 `effective_shape()` 对解析到资产的节点返回 `"mesh"`，而真值全是基本体——
**93% 的物体都解析到了资产，所以这个指标结构性地就是零**。换拟合器也不会动它。

### 创新点二：一个真改进，四条路关闭

**先说唯一活下来的。** `track_rigid` 加了可选的 `rotation_min_gain`：转动必须把配准
残差压低这个相对比例才被接受，否则按「只有平移」解。零假设是「只有平移」。

| 真值类别 | 该怎样 | 基线 | 闸 0.10 |
|---|---|---|---|
| 静止（17 个）| 低于铰链门槛 8° | 0.235 | **0.588** |
| 真在转（15 个）| 高于 8° | 0.200 | **0.200** |
| 纯平移（13 个）| 低于 8° | 0.154 | 0.231 |

静止物体解出的转角中位 **13.81° → 4.30°**，落到门槛以下；**真转动一点没被压**；
位置和漂移都略好（平滑后位移 0.028→0.027、漂移 0.058→0.051）。
局限：低于门槛的比例在 **0.588 饱和**，门槛提到 0.30（只放行 14% 的步）也上不去。

**端到端只值一个物体**：运动类型 0.1923 → 0.2308，26 个配对物体里多对一个。噪声量级。

### 关闭的四条，以及它们为什么指向同一件事

**一、可见子集配准。** 想法是「部分对完整欠定，是因为没告诉它该对哪一部分」，
而相机位姿现成放着没用（`registration.py` 里原本一行相机都没有）。实测三个数全差，
静止转角 13.5° → 24.9°。

**二、全局两遍精化。** 五天前已经否定过（`172d5ae`）：「部分对完整比部分对部分更
欠定」——一块局部表面能滑到完整模型上好几个位置都说得通。我重新提了一遍才发现。

**三、调运动分类的闸。** 一度以为找到了大东西：周期检测的**平移腿方向是对的**
（真·周期平移 r² 0.4152 对真静止 0.1835，**+0.2317**），而**全体过门槛比例 0.000**
（最大 0.609 < `periodic_min_r2` 0.70）。看起来像「一条好腿被一个谁都够不到的闸
关死」。两步证伪：单独降 `periodic_min_r2` 到 0.25，72 个候选新过 r²，**产出一个字
没变**（周期候选的置信度≈它的 r²，真正绑住的是下游 `min_primary_confidence` 0.55）；
两道闸一起降，运动节点从 14 翻到 **26**，`periodic_translate` 终于出现，而
**准确率 0.1429 → 0.1429，一个都没多对**，精确率还降了。
**闸不是在误伤，是在正确地拦截。**

**四、模板配准。** 这条看起来最有希望——合成上限是静止 5.2°、纯平移 5.0°、
真转 90° 保住 89.7°。真实数据上：

| 模板来源（静止 17 个，真值 0°）| 解出范围 | RMSE |
|---|---|---|
| 局部互配（现状）| 19.85° | 13.07° |
| 真值位姿拼的完整模型（**预言机**）| 15.25° | **6.96°** |
| 拟合出来的长方体 | 43.59° | **81.07°** |
| 检索到的资产网格 | 63.71° | **80.92°** |

**两条能落地的模板来源都比现状差六倍**，只有要真值位姿的预言机有效。
而且**预言机会把真转动压没**：spin 真值 114.05°，它只解出 10.04°。
合成上限写明的四个折扣（形状不贴合、检索率 0.51~0.69、深度噪声、互相遮挡）
合起来不是「小很多」，**是把方向都翻掉了**。

### 四条路的失败方式指向同一个根因

`scripts/probe_icp_visibility.py` 早就把它钉死了：

| 条件 | 静止被解出的假转角 |
|---|---|
| 完整点云 | 0.3° ← ICP 本身没问题 |
| 相机绕着走、只留可见面 | 6.9° |
| 固定相机 + 像素格重采样 | 0.0° |
| **相机绕着走 + 像素格重采样** | **26.6°** ← 组合远大于两者之和 |

深度图的采样格子钉在**图像**上不钉在物体上。相机一动，两帧之间连一个共同物理点都
没有——所以无论拿什么去配（相邻帧、完整模型、资产网格、拟合长方体），
**配的都是两块随视角扫动的局部表面**。

**所以缺的不是更好的模板，是让「这一帧该看见什么」可预测的东西。**

> **ICP 没有前向模型。** 给定几何和相机，它不能预测这一帧该看见什么，所以它没有
> 任何依据去否决一个转动。而稠密重建（3DGS）**本身就是一个前向模型**。

这是两个创新点真正合流的地方，也是今天唯一没被证伪的方向。它不是「用更好的深度」，
也不是外观——**是用一个能回答「从这个相机看过去该是什么样」的表征，去约束离散的
程序选择**。

### 方法学：今天被自己推翻了四次

提出时都很有说服力，全部被自己的数推翻：并云汇聚（五天前已否定）、全局精化
（同上）、「转动几乎总挣得到」（实测接受率 0.355~0.548，是我拿 n=5 的中位数看它）、
过时的 `orientation_reliable` 闸（实测只挡住 13%）。

共同形状是**汇总量掩盖分布**，而且每次换一件外衣：

- n=5 的中位数对接受率 20 个百分点的变化纹丝不动；
- 把 `spin` 和 `periodic_rotate` 并在一起算正弦 r²（spin 的角度是斜坡，正弦拟合
  本来就该低）；
- **统计上的可分性（中位差 +0.23）不等于逐物体可用**（重叠严重，放进来的对错各半）。

最危险的一次是：量具瞎掉之后，我**给瞎掉的读数配了一套完整的机制解释**。
那比单纯算错严重——合理的解释会让人停止追查。

### 补：前向模型的预言机——今天唯一三条判据全过的结果

上一节结尾那句「缺的是让『这一帧该看见什么』可预测的东西」，当时只是推断。
做了一个预言机实验验证它（`scripts/probe_icp_visibility.py`，纯合成，十几秒）：
配准之前，用真值可见性把相邻两帧**裁到同一块物理表面**，再做 ICP。

| 运动 | 真值 | 相机绕+像素格（现状）| **裁到公共可见区** |
|---|---|---|---|
| 静止 | 0° | 12.5° | **0.0°** |
| 纯平移 | 0° | 26.9° | **0.8°** |
| 绕 y 轴转 90° | 90° | 90.2° | **90.4°** |

**伪造转动完全消失，而真转动毫发无损。**

第二行和第三行一起看才有意义。今天所有「有效」的修法都在第三行上栽过：转动闸在
纯平移上只做到 0.231 低于门槛；模板配准静止 RMSE 6.96°，代价是把真转的 114° 压成
10°。**只有这条三行全对。**

机制上它和前四条有本质区别：那四条都在「拿什么去配」上做文章，而被配的两边**仍然
是两块随视角扫动的局部表面**；裁到公共可见区是第一个**去掉误差来源**而不是压住它
的做法。

**但它是上界，不是承诺。** 合成里可见性精确可算（法向点乘视线），真实的 3DGS 给不出
这个精度——模板路线就是这么栽的（合成上限 5.2°，落地 81°）。区别在于模板路线的
合成上限**本身就带着真转动被压小的毛病**（冷启动 55.5°），这条没有。

### 所以两个创新点是同一件事

> **稠密重建的价值不在外观，也不在深度精度，而在于它是一个前向模型**——给定几何和
> 相机，它能预测这一帧该看见什么。有了这个，才谈得上在配准前把两帧裁到同一块表面，
> 也才谈得上让连续的几何去否决一个离散的程序选择。

「用连续稠密表征监督离散符号程序」（创新点一）和「做可交互性而不是外观」
（创新点二）在这里合并成一句话：**可交互性卡在位姿，位姿卡在没有前向模型，
而前向模型正是稠密表征能给、而逐帧汇总量给不了的东西。**

落地时必须同时报三行——真转动那行掉了就等于没做。

### 更正：上一节那个「三条判据全过」的结论作废

上一节贴了一个合成实验，说裁到公共可见区能让伪造转动归零而真转动无损，并据此说
「前向模型值得建」。**那个结论是错的，两处。**

**一、在真实点云上不成立。** 把可见性换成真值基本体的**解析法向**（法向估计这个
误差源整个去掉），静止物体（17 个，真值 0°）：

| 做法 | 解出范围 | RMSE |
|---|---|---|
| 局部互配（现状）| 19.85° | **13.07°** |
| 公共可见区·估计法向 | 25.76° | 19.71° |
| 公共可见区·**解析法向** | 28.29° | **14.50°** |

解析法向比估计法向好，**但仍然不如什么都不做**。revolute 那组同样（21.11 对 16.49）。

**二、合成那次测的根本不是可见性裁剪。** 代码里两帧用的是同一组下标：

```python
src = base[both] @ rot_b.T + trans_b
dst = base[both] @ rot_a.T + trans_a
```

src 第 i 个点和 dst 第 i 个点是**同一个物理点**——那是**精确对应关系**的预言机。
而真实数据上每帧的点来自它自己的深度图，**即使裁到同一块区域，两帧采到的仍是不同
的物理点**。而「两帧之间没有共同物理点」正是整个问题的根因——合成实验把根因直接
抹掉了，所以得到 0.0°。

**准确的结论**：可见性裁剪这条路在真实数据上关闭；合成那个 0.0° 说明的是
「有精确对应关系就全好了」，对，但不可操作，因为获得对应关系正是原问题。

### 于是当天关闭了六条，一条都没立住

可见子集配准、全局两遍精化、调运动分类的闸、模板配准（两条模板来源都比现状差六倍）、
公共可见区·估计法向、公共可见区·解析法向。唯一活下来的是转动闸，而它端到端只值
一个物体。

**根因仍然站着，而且现在更清楚它为什么难：**

> 采样格子钉在图像上不钉在物体上，相机一动，两帧之间**连一个共同物理点都没有**。

六条修法里有五条是在「拿什么去配」或者「配哪一块」上做文章，而**只要两边的点不是
同一批物理点，这些都改变不了问题的性质**。唯一真正解决它的是精确对应关系，
而那正是原问题。

所以下一步要么换信号（特征点对应，#79 那条），要么接受这一级拿不到可靠转动、
把可交互性的重心放到不依赖转动的那两档（观测运动、直接操纵——它们本来就立得住）。

### 方法学：当天最贵的一条

**预言机实验最容易把真实条件里最难的那一项也一并理想化掉，而那一项往往就是问题本身。**
当天连续两次「实现的东西 ≠ 声称要测的东西」，第二次还拿着那个数对外说了
「唯一三条判据全过」。写完预言机、看到结果之前，要先逐条列出「真实情况下哪些东西
我没有」，再回去确认实现里是不是把它们偷偷给了自己——尤其是**对应关系、位姿、分割**。

### 补：对应关系这条路也测完了，四个变体全输给 ICP

上一节说「下一步要么换信号（特征点对应，#79），要么接受这一级拿不到可靠转动」。
把前一条做完了：把 ICP 换成**跨帧特征点对应**（光流跟踪 + Kabsch 闭式解，
完全不经过最近邻匹配），四个变体：

| 变体 | 静止物体 RMSE |
|---|---|
| 稀疏角点 + 链式累积 | 45.52° |
| 稠密全像素 + 链式累积 | 103.73° |
| 全像素 + **锚定第 0 帧** | **58.88°** |
| 角点 + 锚定 | 69.92° |
| **ICP（现状）** | **13.07°** |

**全部比 ICP 差 3.5~8 倍**，而且这一轮深度是真值渲染、掩码是真值、所有能想到的
混杂都单独排除过：

- **链式累积**是个真混杂（`track_rigid` 的注释早就写明链式不行），修成锚定之后
  103.73 → 58.88；
- **点太少**：普查 587 个物体-帧样本，角点中位只有 **4 个**，掩码面积中位 **264 像素**
  （约 16×16）。稠密光流把点数拉到 264 个，没用；
- **点不可跟**（平坦区的孔径问题）：换回角点 + 锚定，更差；
- **边界深度跳变**：掩码腐蚀两格，更差。

**结论反直觉但很硬：**

> ICP 那种「原理上错但一致」的最近邻对应，打赢了光流那种「原理上对但很噪」的真对应。
> ICP 用几千个点，单点误差被平均掉；光流只有几十个跟踪点且会漂移，几个坏点就能把
> Kabsch 解歪几十度。**在小物体、低纹理的合成渲染上，「多而糙」赢了「少而精」。**

**这不等于对应关系这个想法错了。** 合成实验证明有**精确**对应时三行全对
（静止 0.0°、纯平移 0.8°、真转 90° 保住 90.4°）。它说的是**光流在这批数据上拿不到
足够好的对应**。要再试，得换更强的跟踪器（CoTracker / TAPIR 这类学出来的点跟踪）
或者有纹理的数据，而不是再调 LK 的参数。

### 一个比方法更要紧的发现：评测看不见「挑了哪个资产」

创新点一兑现不了，查到最后不是方法的问题，是**指标空间里没有那个量**。

把资产检索的重排改掉（用观测到的包围盒边长比例去挑资产），**选中的资产确实变了**：

```
test_00000   关: minigolf/ball-blue  minigolf/ball-green  car/debris-door
             开: food/rice-ball      minigolf/ball-blue   castle/door
```

重排生效 119 次。而**每一个指标逐字节相同**——物体召回、精确率、场景召回、
`shape_ok`、`scale_ok`、`shape_error`、运动类型、轨迹误差，一个都没动。

原因是这样的：

| 指标 | 为什么看不见资产 |
|---|---|
| `shape_kind_accuracy` | 资产节点一律记成 `"mesh"`，而真值全是基本体 → 恒零 |
| `shape_ok` / `scale_ok` / `shape_error` | 读的是节点的 `extent`，而资产节点的 extent 来自**观测**，不是来自网格 |
| `object_recall` / `object_precision` | 只看位置 |
| `class_accuracy` | 只看类名 |

**没有任何一个指标看得见网格本身**，而资产决定了场景实际长什么样——
那恰恰是老师看到自拍视频对照图时问「为什么比不上 3DGS」的那个东西。

所以这一整块**从来没有被量过**。「换个更好的检索」在表上永远是零变化，
不是因为没用，是因为表不看它。

补上的 `asset_shape_error` 拿**选中资产自己的**边长比例和真值节点比，口径和
`shape_scale_agreement` 一致，所以两个数可以并排读：

* `shape_error` —— 我们把这个物体**画成了**多大多扁；
* `asset_shape_error` —— 我们**挑的那个网格本身**多扁。

材料是现成的：4812 个资产的边长比例一次性预计算好（零失败，
`scripts/build_asset_shape_cache.py`）。

### 这对基准那一节意味着什么

上面「我们手里已有、别人没有的」那一节要加一条限定：**我们的评测目前只覆盖几何
摆位和运动，不覆盖「长得像不像」**。而 LEGO-Bench 那一批是**量外观的**
（重渲染后逐像素比，误差 ≤ 30/255 的像素占比）。

这解释了一件之前没想通的事：为什么「外观」在我们的表上一直是个盲区，
而老师一眼就看出来了。**人眼看的正是评测没看的那一半。**
