这个版本把整条管线跑通的结果打包出来了。给一段十几秒到一分钟的普通视频，程序自动认出里面的场景和会动的东西，写成一份场景程序，再编译成一个能在浏览器里玩的 three.js 小游戏。中间没有人工建模，也没有人手写场景，连场景程序都是模型看着视频关键帧和感知结果写出来的。

## 先看这个

demo.mp4 是三段并排对比接在一起的总览。左边是原视频，右边是生成出来的游戏用同一条相机轨迹渲染的画面，可以直接对着看恢复得准不准。不想下载 zip 的话看这一个就够了。

## 三个包

gwm-plarail-train.zip 是一段玩具火车在地板轨道上跑的视频跑出来的结果。

gwm-conveyor-boxes.zip 是一段工厂气动输送线的俯拍视频跑出来的结果。

gwm-handwritten-playground.zip 是我们自己渲染的合成场景，带逐帧真值，用来在没有外部视频的时候验证管线本身。

每个包里都有原视频、把感知结果画回视频上的检查视频、按原相机回放的游戏画面、自动试玩的录像、场景程序、运行报告，以及可以独立运行的游戏。

## 怎么玩

解压之后在包目录里执行

    python3 serve.py

浏览器会自动打开。WASD 或方向键移动，空格跳，R 在回放和游玩之间切换。左上角显示收集了几个物件、死了几次、到没到终点。不能直接双击 index.html，浏览器不允许本地文件加载 ES 模块。

包里的 program.json 就是这个游戏的全部内容，一份 JSON，改里面的数字再刷新页面游戏就变了。

## 想自己跑一段视频

仓库里的 RUNNING.md 写了怎么装、怎么跑，分成在自己电脑上和在 HPC 集群上两种情况，也写清楚了需要多少内存多少磁盘。简单说是 Python 3.10 以上、Node 20 以上、ffmpeg，权重下载 9.6 GB，内存 8 GB 起步，显卡可有可无。一条 20 秒的视频在 16 核的机器上大约 4 分钟跑完。

## 现在做到什么程度

三段视频都能从头走到尾，自动试玩都能走到终点。场景的几何还很抽象，物体都是方块和圆柱这样的替身，因为这一版还没接素材库。运动的判断在合成场景上比较准，升降平台、定时开关的门、来回跑的矿车都认对了；在真实视频上还不稳，相机一动静止的东西容易被判成在动。模型写出来的程序目前和直接从证据翻译差不多，修订环节提得出修改但还没带来提升。具体数字和已知问题在仓库的 docs/status.md 里。
