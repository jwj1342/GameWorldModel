# 进展

最后更新 2026-11-27。每个实验的问题、答案和出处逐条记在 [`experiments/index.csv`](../experiments/index.csv)，这里只写现在站在哪。

## 现在在想什么

方向还在构思。现在的想法是把世界当成一份运行着的代码：布局、部件、关节、行为和状态都写在代码里，外观是这份代码渲染出来的样子；观测和渲染对不上时，由编码智能体回头改代码。细节和讨论在 #99：世界按需展开成一棵树，哪些节点要细化、什么时候细化，都是要回答的问题。

最近一次讨论的共识是：重建出代理几何、接上物理和渲染都不难，难的是让代码在物体很多、状态不断变化时一直维护住世界状态，以及一开始就要定下的粒度（一个杯子摔碎了算一个状态还是几个）。评价方式也得有现实里的锚点，不能只让智能体互评。

## 正在做的

**两轴评测 demo**（#98、#100，说明在 [`bench-demo.md`](bench-demo.md)，代码在 `gwm/bench/`）。编码智能体看着一个真实房间的照片写出 three.js 场景代码，一边在留出视角上量它像不像（PSNR、SSIM、LPIPS、深度），一边在物理引擎里执行它从没见过的交互清单和连续操作，看它能不能用。在 Mip-NeRF 360 的 room 上第一轮的结果：

- 差距在外观，不在布局。代码场景纯色渲染 PSNR 13.9、LPIPS 0.613；本机 3DGS 32.2、0.171。把训练照片的颜色投到代码场景的几何上就到 24.5、0.230，同样投到 3DGS 的几何上是 31.6、0.159。只做曝光和白平衡校正只到 16.4、0.593。最终版比中途快照差的 1.5 dB 全在灯光上。
- 代码场景的几何深度误差中位数 3.8 厘米，3DGS 三次是 1.6、3.8、1.65 厘米。
- 单步交互清单已经饱和：给过物体名单的运行全部是 29/30，分不出好坏；连续操作序列还有区分度。
- 同一设置跑三次，PSNR 波动 ±1.3 dB，所以每个条件至少跑三次。
- 评测有泄露：智能体的工作区在仓库里，读得到别的运行写的代码。隔离做好之前不跑新的智能体运行。

**状态差分预实验**（#92，设计在 [`statediff-pilot.md`](statediff-pilot.md)）。两帧图加一句话，让 8B 的多模态模型直接写场景程序。LoRA 训练后格式、物体数、尺寸都学会了，位置没学会：水平位置误差中位数 6.44 米，比「全猜训练集平均位置」的 5.17 米还差。结论是不再直接回归世界坐标，改成在图像平面上定位、再由内核抬升到三维。

**铰接探针**（分支 `pre/articulation-probe`，还没合进 main）。给两帧、一句话和全部几何，只让模型写关节。用内核在程序空间里搜出来的伪标签做自训练，没见过的构型上成功率从 0.29 升到 0.56，和用真值标签自训练一样；采样后做偏好优化没有提升。

## 冻结的部分

第一阶段的几何管线（视频 → 感知 → 运动 → 关节 → 素材检索 → 场景程序）从 2026-11-03 起冻结，只留作对照。仓库首页 README 描述的就是这一阶段。它在真实视频上卡在几处：位姿和尺度估不准、运动和静止分不清、物体碎片化；试过的判据和修法大多没立住，每一条都记在 `experiments/index.csv`。代码（`gwm/perception/`、`gwm/synthesis/` 等）保留，能跑，但不再往上加功能。

## 早期踩过、现在仍然有效的坑

- 编码通道不能经过任何后处理。内核渲染开了抗锯齿时，物体 ID 通道在边缘混出不存在的编号；three.js 默认输出 sRGB 时，ID 和深度通道被 gamma 变换。现在无头渲染关掉了抗锯齿，这两个通道用线性输出，`scripts/check_id_pass.py` 在冒烟流程里检查。
- 集群计算节点的代理放行 GitHub、HuggingFace 和各家模型 API，但不放行 npm、Playwright 的浏览器下载、HuggingFace 的 CDN 大文件和 arXiv。这类东西在登录节点下载。
- vllm 和感知用的 torch 版本冲突，所以分成两个 venv；两轴评测又单独一个（见 `scripts/setup_bench_env.sh`）。
