# 实验

`index.csv` 是实验索引：每个跑过的问题一行，写清问的是什么、答案是什么、代码和结果在哪。没成立的也登记，写清是怎么排除的。下次想试一个点子之前先在这里搜一下，很多路已经走过。

需要单独说明的实验（比如有自己的输入文件）在这里开一个子目录，比如 `editability/`。设计较长的写成 `docs/` 下的一篇文档，在索引里链过去。

## 各列的意思

- `date`：得出结论的日期。
- `line`：属于哪条线，比如感知、运动、关节、资产检索、尺度与相机、几何与精细度、状态差分预实验、两轴评测、训练。尽量复用已有的名字。
- `question`：一句话的问题。
- `answer`：一两句话的答案，带关键数字。数字要能在 `results` 或 `issue_pr` 里找到出处。
- `verdict`：`成立`、`不成立`、`部分成立`、`待定`。
- `code`：用到的脚本、模块、配置，用「; 」隔开。只列 main 上有的；notes 里写着「在标签 geometry-pipeline-frozen 上」的，用 `git show geometry-pipeline-frozen:<路径>` 看。
- `results`：`docs/results/` 下的结果目录。
- `issue_pr`：对应的 issue 或 PR。
- `notes`：比如「后来被 #NN 推翻」「这个数是循环的」。

## 做一次实验

1. 作业脚本写在 `jobs/`，产物写进 `work/<路线>/<YYYYMMDD>-<名字>/`，目录里放 `run.json` 和作业脚本的副本。
2. 新路径先拿一条数据冒烟，跑通再上全量。
3. 要留给别人看的结果挪进 `docs/results/<名字>/`。`work/` 在 scratch 上，闲置会被清理。
4. 在 `index.csv` 里加一行。结论推翻了以前某一行的，在那一行的 `notes` 里写上。

## 量具上踩过的坑

下面这些都在这个仓库里真实发生过，方向全是让结论看起来比实际干净。下结论之前对着查一遍：

- 带量纲的阈值（米、像素）换了尺度没跟着缩，等于什么都算对。
- 两套口径的数放进同一张表比，比如探针直接喂真值，评测走完整链路。
- 对一串 0 和 1 取中位数，只会得到 0 或 1。
- 被评测的量写进了配对或筛选条件：先用结论挑样本，再在样本上算结论。
- 预言机或模板把答案写进了题面，于是得到一个假的满分。
- 类别不平衡时看准确率；要跟「恒答多数类」的基线比。
- 「离最近的那个有多远」这类归因，没配密度相当的随机对照。
- 空对空算满分或算零（画面外的物体、空掩码），把平均值拉偏。
- 推翻一个判据之后没回头查它还被用在哪里。
- 对照组和实验组之间不只差一个变量（中间隔了几个提交）。
- 在错误的管线位置估一道闸的代价，比如用最终产物去估一道跑在中间的闸。
- 只看一个均值或中位数：先看样本量和分布。
- 同一设置只跑一次就下结论；智能体运行同设置的波动可以和要测的差一样大。
